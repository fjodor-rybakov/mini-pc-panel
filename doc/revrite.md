Перепиши проект `mini-pc-panel` (оригинал на Node.js из репозитория `fjodor-rybakov/mini-pc-panel`) на язык **Go** для работы в Linux в качестве фонового демона.

### 1. Стек библиотек (обязательно использовать)
* **Работа с USB HID (экран):** `github.com/sstallion/go-hid` (учитывай, что при необходимости проект должен собираться как с дефолтным бэкендом `hidraw`, так и с `-tags libusb`).
* **Рендеринг графики и шрифтов (замена `node-canvas`):** `github.com/tdewolff/canvas` и его растеризатор `renderers/rasterizer`.
* **Работа с USB Serial (LED-лента):** `go.bug.st/serial`.
* **Сбор системных метрик:** `https://github.com/shirou/gopsutil` (а для температур CPU/NVMe при необходимости чтение `/sys/class/hwmon/`).

### 2. Спецификация протокола экрана (USB HID)
* **Идентификаторы устройства:** `VID = 0x04D9`, `PID = 0xFD01`.
* **Выбор интерфейса:** Устройство имеет два HID-интерфейса (`MI_00` и `MI_01`). Нужно фильтровать устройства через `hid.Enumerate` и открывать строго интерфейс с `InterfaceNbr == 1` (`MI_01`).
* **Формат пакетов:** Любая команда отправляется буфером строго фиксированного размера **4104 байта** (8 байт заголовок + 4096 байт полезных данных, неиспользуемые байты заполняются `0x00`). *Примечание для `go-hid`: если контроллер не использует Report ID, предусмотри добавление нулевого байта `0x00` в начало буфера (итого 4105 байт при вызове `dev.Write`).*
* **Список команд:**
  1. `set_orientation`: `[0x55, 0xA1, 0xF1, orientation, 0, 0, 0, 0]`, где `orientation`: `0x01` = landscape (320x170), `0x02` = portrait (170x320).
  2. `set_time` / `heartbeat`: `[0x55, 0xA1, subcmd, hour, minute, second, 0, 0]`, где `subcmd`: `0xF2` = heartbeat, `0xF3` = set time.
  3. `redraw` (полная перерисовка всего экрана, 108 800 байт = 27 чанков по 4096 байт; последний 27-й чанк содержит 2304 байта пикселей + нули до 4096):
     * Заголовок: `[0x55, 0xA3, subcmd, seq, offset_lo, offset_hi, len_lo, len_hi]`.
     * `subcmd`: `0xF0` (для `seq == 0x01`), `0xF1` (для `seq` от `0x02` до `0x1A`), `0xF2` (для последнего пакета `seq == 0x1B`).
     * `offset` (uint16 LE): смещение в байтах (`0x0000`, `0x1000`, `0x2000`... переполняется после `0xF000` обратно в `0x0000` на `seq == 0x11`).
     * `length` (uint16 LE): `0x1000` (4096) для пакетов `0x01..0x1A` и `0x0900` (2304) для пакета `0x1B`.
  4. `update` (частичное обновление области экрана):
     * Заголовок: `[0x55, 0xA2, x_lo, x_hi, y_lo, y_hi, width, height]` (координаты `x`, `y` в Little-Endian uint16; `width` и `height` в uint8).
     * Размер данных `width * height * 2` не должен превышать 4096 байт.

### 3. Формат изображения и рендеринг (`tdewolff/canvas`)
* **Разрешение:** `320x170` пикселей.
* **Конвертация цвета:** После растеризации холста в `*image.RGBA` (через `rasterizer.Draw(c, canvas.DPMM(1.0), canvas.DefaultColorSpace)`), каждый пиксель конвертируется в **16-битный RGB565 с перестановкой байтов (SWAPENDIAN / Big-Endian)**:
  * `rgb565 = ((r & 0x1F) << 11) | ((g & 0x3F) << 5) | (b & 0x1F)`
  * В буфер записывается сначала старший байт (`byte(rgb565 >> 8)`), затем младший (`byte(rgb565 & 0xFF)`).
* **Учет осей:** Помни, что в `tdewolff/canvas` начало координат `(0, 0)` находится в левом нижнем углу.

---

### 4. Спецификация протокола LED-ленты (USB Serial)
* **Устройство:** чип USB-UART **CH340** (`/dev/ttyUSB*`).
* **Формат пакета (5 байт):** `[0xFA, theme, intensity, speed, checksum]`.
  * `theme`: `0x01` = rainbow, `0x02` = breathing, `0x03` = color cycle, `0x04` = off, `0x05` = automatic.
  * `intensity`: `0x01` (макс) .. `0x05` (мин).
  * `speed`: `0x01` (быстро) .. `0x05` (медленно).
  * `checksum`: младший байт суммы первых 4 байт (`byte((0xFA + theme + intensity + speed) & 0xFF)`).

---

### 5. Требования к архитектуре кода на Go
1. **Конкурентность и тайминги:** Прошивка контроллера HT32 зависает при слишком частой отправке данных. Реализуй единую очередь отправки (канал) и одну горутину-воркер, которая единолично пишет в `hid.Device` с обязательной паузой **10 мс** между пакетами.
2. **Жизненный цикл:**
   * При старте: `set_orientation` -> `set_time` -> полная отрисовка экрана (`redraw`).
   * В фоне: отдельный тикер строго раз в **1 секунду** отправляет пакет `heartbeat` (`0xA1 0xF2`).
   * Отдельный тикер обновляет метрики системы и отправляет только изменившиеся зоны экрана через команду `update` (`0xA2`) или полный кадр при смене экрана/темы.
3. **Graceful Shutdown:** Корректная обработка сигналов `SIGINT` / `SIGTERM` с закрытием USB-дескрипторов.
4. **Структура проекта:** Разбей код на чистые пакеты (`internal/display`, `internal/led`, `internal/render`, `internal/metrics`, `internal/config`) и предоставь готовый `go.mod`, инструкции по сборке и пример конфигурации (JSON/YAML).

Сначала спроектируй структуру файлов и напиши базовую реализацию всех модулей, строго соблюдая протокол байтов выше.
